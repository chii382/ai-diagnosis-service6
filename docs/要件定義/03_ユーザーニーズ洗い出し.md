# ユーザーニーズ洗い出し

## 1. 目的

3タイプのペルソナがLP訪問からCTA押下までに満たしたいニーズを整理し、LPのコンテンツ・UI・非機能要件へ変換する。

## 2. ニーズの分類

- 機能的ニーズ：何を知り、何を行える必要があるか
- 感情的ニーズ：どのような安心感・納得感を得たいか
- 社会的ニーズ：自分の状況をどのように捉え、説明したいか
- 利用上のニーズ：端末、時間、操作性、アクセシビリティ上の期待

## 3. 共通ニーズ

| ID | ニーズ | 背景・理由 | LP要件 | 優先度 |
|---|---|---|---|---|
| N-01 | 短時間で診断できると知りたい | 長い自己分析や診断は負担 | ヒーローに「5問」を明示する | Must |
| N-02 | 診断で何が得られるか知りたい | 結果が抽象的だと試す価値を感じない | 適性のある方向性とキャリアロードマップが得られることを明示する | Must |
| N-03 | 自分が対象か判断したい | 学生向け・転職者向けなど対象が不明だと離脱する | 学生、転職検討者、20〜30代のキャリア検討層を含む表現にする | Must |
| N-04 | 利用の流れを事前に知りたい | 先の見えない操作は心理的負担 | 3ステップを順序付きで表示する | Must |
| N-05 | 安心してCTAを押したい | 料金、登録、情報利用への警戒 | 確定した利用条件と必要なポリシー導線を表示する | Must |
| N-06 | 自分向けの結果を期待したい | 一般論だけの診断を避けたい | AIが回答をもとに個別に整理することを説明する | Must |
| N-07 | 結果を過信せず参考にしたい | キャリア判断をAIに決められたくない | 選択肢整理を支援するサービスとして表現する | Should |
| N-08 | スマートフォンで快適に見たい | 移動中・隙間時間の利用が多い | モバイルファースト、押しやすいCTA、読みやすい文字組み | Must |
| N-09 | ページをすぐ表示してほしい | 表示待ちで離脱しやすい | 画像・フォント・JSを最適化し、Core Web Vitalsを考慮する | Should |
| N-10 | 誰でも操作・理解できてほしい | 視覚、入力手段、理解度には差がある | セマンティックHTML、キーボード操作、コントラスト、代替テキスト | Must |

## 4. ペルソナ別ニーズ

### P1：就活の方向性に迷う学生

| ID | ユーザーストーリー | 潜在ニーズ | 対応方針 |
|---|---|---|---|
| S-01 | 就活生として、自分に合う仕事の方向を知りたい。エントリー先を考える軸がほしいから。 | 自己理解、選択肢の絞り込み | 「強み・適性の整理」を特徴に含める |
| S-02 | 初めて利用する者として、難しい知識なしで試したい。職業知識に自信がないから。 | わかりやすさ | 平易な日本語と短い説明を使う |
| S-03 | 学生として、無料か、登録が必要かを知ってから始めたい。気軽に試したいから。 | 透明性、安心 | 条件確定後、CTA近くに明示する |

### P2：転職を検討する社会人

| ID | ユーザーストーリー | 潜在ニーズ | 対応方針 |
|---|---|---|---|
| W-01 | 忙しい社会人として、短い時間で方向性を整理したい。長い診断を続けられないから。 | 時間効率 | 「5問」と簡潔な3ステップを目立たせる |
| W-02 | 転職検討者として、経験を活かせる次の選択肢を知りたい。キャリアを無駄にしたくないから。 | 継続性、納得感 | ロードマップが次の一歩を整理することを示す |
| W-03 | 個人として、入力情報がどう扱われるか知りたい。不要な連絡を避けたいから。 | プライバシー | プライバシーポリシー導線と事実に基づく説明を用意する |

### P3：キャリア停滞を感じる若手・中堅

| ID | ユーザーストーリー | 潜在ニーズ | 対応方針 |
|---|---|---|---|
| C-01 | 将来に悩む社会人として、転職以外も含めて方向性を考えたい。選択肢を狭めたくないから。 | 選択の幅 | 転職だけを前提にしないコピーにする |
| C-02 | 経験のある社会人として、適職名だけでなく行動計画を知りたい。実行につなげたいから。 | 具体性、行動可能性 | ロードマップの価値を中心に訴求する |
| C-03 | 慎重な利用者として、AIの提案を参考情報として使いたい。人生を断定されたくないから。 | 自律性、信頼 | 誇大表現を避け、意思決定支援と位置づける |

## 5. ニーズから導くLPコンテンツ要件

### ヒーローセクション

- 主見出しで「5問でわかる、あなたのキャリア」を提示する
- サブコピーで「回答をAIが分析し、適性のあるキャリアロードマップを作成する」ことを説明する
- 主要CTAは1種類に絞り、診断開始行動がわかるラベルにする
- 対象者、料金、所要時間、登録要否のうち確定している重要条件をCTA付近に置く

### サービス特徴3つ

1. 手軽さ：5問で短時間に回答できる
2. 個別性：AIが回答内容をもとに方向性を整理する
3. 行動可能性：適性だけでなく、次の一歩をロードマップで示す

### 診断の流れ（3ステップ）

1. 5つの質問に答える
2. AIが回答を分析する
3. キャリアロードマップを確認する

### 下部CTA

- 特徴と流れを理解した後の主行動として配置する
- ヒーローCTAと同じ遷移先にする
- CTAの直前に「何が得られるか」を短く再提示する

### フッター

- サービス名またはロゴ
- コピーライト
- 運営者情報、利用規約、プライバシーポリシーへの拡張可能なリンク領域
- 未作成ページへのリンクを表示する場合はリンク切れを発生させない

## 6. 非機能・品質ニーズ

| 分類 | 要件 |
|---|---|
| レスポンシブ | スマートフォンを主軸に、タブレット・デスクトップでも情報順序を維持する |
| アクセシビリティ | WCAG 2.2 AAを目標とし、見出し構造、フォーカス、コントラスト、代替テキストを考慮する |
| パフォーマンス | Next.jsの最適化機能を活用し、不要なクライアントコンポーネントと大容量画像を避ける |
| SEO | title、description、OGP、意味のある見出し階層を設定できるようにする |
| 信頼性 | AIや診断精度を保証する断定表現、根拠のない実績・利用者数を掲載しない |
| 保守性 | MUIのテーマと共通コンポーネントを用い、色・余白・タイポグラフィを一元管理する |
| 計測 | CTA設置位置を区別してイベント計測できる設計にする |

## 7. 未確定事項

実装前にプロダクト責任者が決定する必要がある。

- 診断の料金（無料か、有料機能を含むか）
- 診断の想定所要時間
- 診断開始前後の会員登録要否
- CTA押下先URLと、診断機能未公開時の挙動
- 回答データ、アクセス解析データの取得・保存・利用方針
- AI分析の説明範囲と免責表示
- 運営者情報、利用規約、プライバシーポリシーの公開URL
