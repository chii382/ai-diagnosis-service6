# MVP機能一覧と優先順位

## 1. 目的

Stage1で制作するトップページ（LP）について、必要な機能とコンテンツを優先順位付きで定義する。

## 2. スコープ

### Stage1に含む

- LPの1ページ構成
- サービス紹介
- 特徴3つ
- 診断の流れ3ステップ
- 診断開始CTA（ヒーロー、ページ下部）
- フッター
- レスポンシブ、基本アクセシビリティ、SEOメタデータ

### Stage1に含まない

- 5問の質問・回答UI
- AIによる分析処理
- 診断結果・キャリアロードマップ画面
- 認証、会員情報管理
- 決済
- 回答履歴、結果保存・共有
- 管理画面、CMS

## 3. 優先順位の定義

MoSCoW法を用いる。

- Must：Stage1の目的達成または公開品質に不可欠
- Should：重要だが、暫定対応でも公開可能
- Could：価値はあるが、MVP検証後に判断可能
- Won't：Stage1では実装しない

## 5. コンテンツ優先順位

| 順位 | メッセージ | 理由 |
|---|---|---|
| 1 | 5問で診断できる | 第一印象で負担の小ささを伝えるため |
| 2 | AIが回答を分析する | サービスの仕組みを理解してもらうため |
| 3 | キャリアロードマップが得られる | CTA押下による便益を具体化するため |
| 4 | 学生・転職検討者・20〜30代が対象 | 自分向けか判断できるようにするため |
| 5 | 3ステップで利用できる | 開始後の不確実性を減らすため |
| 6 | 料金・時間・登録・データ取扱い | 不安を解消するため。内容確定後に掲載する |

## 6. 技術実装方針

### Next.js 15 / App Router

- LPは原則Server Componentで構成する
- ブラウザAPIやイベント処理が必要な最小部分のみClient Componentにする
- `metadata` または `generateMetadata` でSEO・OGP情報を定義する
- CTA遷移にはNext.jsの`Link`等、遷移先に適した仕組みを使う
- 画像を使用する場合は`next/image`を基本とする

### MUI

- Themeでブランドカラー、タイポグラフィ、ブレークポイント、余白を一元管理する
- `Container`、`Stack`、`Grid`等を用いて一貫したレイアウトを作る
- CTAは共通コンポーネント化し、ラベル・遷移・計測位置を明示的に渡せるようにする
- MUIとApp RouterのSSR設定は、採用するMUIバージョンの公式手順に合わせる

### コンポーネント案

| コンポーネント | 責務 |
|---|---|
| `HeroSection` | 主見出し、サブコピー、ヒーローCTA |
| `FeatureSection` | 特徴3つの見出し・説明 |
| `HowItWorksSection` | 診断の3ステップ |
| `BottomCtaSection` | 便益の再提示と下部CTA |
| `DiagnosisCta` | CTAの見た目、遷移、設置位置識別 |
| `SiteFooter` | サービス情報、コピーライト、法務リンク |

## 7. Must要件の受け入れ基準

| 対象 | 受け入れ基準 |
|---|---|
| 表示 | LPの全5セクションがエラーなく表示される |
| 内容 | 5問、AI分析、キャリアロードマップの3点が明記される |
| 特徴 | 異なる価値を持つ特徴が3つ表示される |
| 流れ | 3ステップが正しい順序で理解できる |
| CTA | 2か所のCTAが同じ有効な遷移先に移動する |
| レスポンシブ | 主要幅で横スクロール、要素重なり、文字切れがない |
| 操作 | CTAをキーボードで選択・実行でき、フォーカスを視認できる |
| セマンティクス | ページに主見出しが1つあり、見出し順序が論理的である |
| SEO | 固有のtitleとdescriptionが出力される |
| 品質 | ビルド、lint、型チェックのうちプロジェクトに設定された検証が成功する |

## 8. 実装前の決定事項

以下が未決定の場合、仮文言・仮リンクで公開せず、プロダクト責任者と確定する。

1. CTAの正式ラベルと遷移先
2. 料金、所要時間、登録要否
3. ブランド名表記、ロゴ、カラー、トーン
4. 運営者名、コピーライト表記
5. 利用規約・プライバシーポリシーの公開有無とURL
6. アクセス解析基盤、Cookie等の同意要否、イベント命名
7. OGP画像とSNS表示文言

## 9. Stage1完了条件

- Must項目がすべて実装され、受け入れ基準を満たす
- CTA押下先が有効であり、Stage1の終了地点が明確である
- 未確定事項が解消され、掲載文言が実際のサービス条件と一致する
- モバイルとデスクトップで目視確認を完了する
- Stage2対象の診断機能が、誤って提供済みであるかのように見えない
