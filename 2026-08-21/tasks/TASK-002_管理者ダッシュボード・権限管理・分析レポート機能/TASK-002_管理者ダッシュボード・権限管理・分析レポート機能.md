# TASK-002 管理者ダッシュボード・権限管理・分析レポート機能

## ユーザーニーズ

- 管理者は、サービスの利用状況と稼働状態を一画面で把握したい。
- 管理者は、ユーザーを検索し、必要な利用者へ安全に管理者権限を付与・解除したい。
- 管理者は、診断数や完了率、自己理解プロフィール、属性別の傾向を期間別に確認したい。
- 管理者は、集計結果をCSVで出力し、運営レポートや追加分析に利用したい。
- 管理者は、アプリケーションエラーを一覧で確認し、Sentry上の詳細調査へ移動したい。
- 一般ユーザーは、管理者画面や管理APIへアクセスできない状態で安心して利用したい。

## 仕様要件

### 認証・権限

- Userに `role: "admin" | "user"` を追加し、既定値は `user` とする。
- NextAuth.js v5のJWTとセッションへroleを引き継ぐ。
- `/admin/:path*` はミドルウェアでログインとadminロールを検証し、未ログインはログイン画面、権限不足は `/dashboard?error=forbidden` へ遷移する。
- 全管理APIでもサーバー側でadminロールを再検証し、未認証は401、権限不足は403を返す。
- 最後の管理者が自分自身をuserへ変更する操作は禁止し、管理者不在を防ぐ。

### 管理者画面

- `/admin`: 本日の分析数、総分析数、直近30日以内のアクティブユーザー数、最近の分析5件、DB接続状態、API応答時間、クイックアクションを表示する。
- `/admin/users`: MUI DataGridによるページネーション、メール・名前検索、ロール絞り込み、ロール変更、診断回数・最終診断日時・最終ログイン日時を表示する。
- `/admin/analytics`: 日別・週別・月別の切替グラフ、自己理解プロフィール（現在の状況、強み、価値観、業界）のTOP10、分析完了率、年代・状況・業界別傾向を表示する。
- `/admin/errors`: Sentry Issues APIから取得したエラーを一覧表示し、設定されていない環境では設定案内を表示する。
- 管理画面共通ナビゲーションにはMUIのCard、Chip、Tab、Avatarを使用する。

### API

- `GET /api/admin/users`: `page`, `pageSize`, `search`, `role` を受け取り、ユーザー一覧と総件数を返す。
- `PATCH /api/admin/users`: `userId`, `role` を検証し、対象ユーザーのロールを更新する。
- `GET /api/admin/analytics`: `period=daily|weekly|monthly` に応じた時系列、TOP10、完了率、属性傾向、ダッシュボード指標を返す。
- `GET /api/admin/analytics?format=csv`: 同じ期間の時系列集計をUTF-8 BOM付きCSVで返す。
- `GET /api/admin/errors`: Sentry APIのIssue一覧を正規化して返す。
- 外部APIやDBの失敗はSentryへ送信し、通知Webhook設定時はSlackまたはDiscordにも通知する。

### データ・環境変数

- User: 既存フィールドに `role` を追加する。未設定データはuserとして扱う。
- 診断完了率は、診断を1件以上完了したユーザー数 ÷ 全ユーザー数で算出する。
- アクティブユーザーは `lastLoginAt` が直近30日以内のユーザーと定義する。
- 必須環境変数は既存の `MONGODB_URI`, `AUTH_SECRET`。Sentry利用時は `NEXT_PUBLIC_SENTRY_DSN`、一覧取得時は `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN` を設定する。
- 初回管理者は `ADMIN_EMAILS` にメールアドレスを設定してログインし、その後ユーザー管理から追加の管理者を設定する。
- 任意通知は `ADMIN_ERROR_WEBHOOK_URL` を設定し、Slack/Discord互換Webhookへ送信する。

## 処理手順設計

### 管理者アクセス

1. ミドルウェアが `/admin` 以下へのリクエストを受ける。
2. JWTセッションがなければ、元URLをcallbackUrlとしてログイン画面へ遷移する。
3. セッションのroleがadminでなければ、一般ダッシュボードへ遷移する。
4. 各ページ・APIでもセッションを検証し、権限の二重チェックを行う。

### ダッシュボード・分析

1. 管理画面が `/api/admin/analytics` を呼び出す。
2. APIがUserとDiagnosisを集計し、KPI、最近の診断、期間別件数、TOP10、属性別傾向を生成する。
3. 画面はCard、Chip、Rechartsで結果を表示する。
4. CSV出力時は現在選択中の期間をクエリへ付けてダウンロードする。

### ユーザー管理

1. 検索・ロール・ページ条件を `/api/admin/users` へ送る。
2. APIは条件に一致するusersを取得し、診断履歴を集計して返す。
3. 管理者がroleを変更するとPATCH APIを呼び出す。
4. APIは入力、対象ユーザー、最後の管理者制約を確認後に更新し、一覧を再取得する。

### エラー監視

1. Sentry SDKがブラウザー・サーバー・Edgeの未処理例外を収集する。
2. `/api/admin/errors` がSentry Issues APIを呼び出し、管理画面用に整形する。
3. Sentry設定が不足している場合は空一覧と不足設定を返し、画面に案内する。
4. 管理APIで捕捉した重大エラーはSentryへ送信し、Webhook設定時は通知する。

## 受け入れ条件

- adminは4つの管理画面と3つの管理APIを利用でき、userはアクセスできない。
- ダッシュボードに3つのKPI、最近の分析5件、システム状態、クイックアクションが表示される。
- ユーザー一覧を検索・絞り込み・ページ移動でき、admin/userを安全に変更できる。
- 分析グラフを日別・週別・月別で切り替え、TOP10と属性傾向を確認できる。
- 表示中期間のCSVをダウンロードできる。
- Sentry設定時はエラー一覧を表示し、未設定時も画面が壊れず設定案内を表示する。
- 型チェックと本番ビルドが成功する。
