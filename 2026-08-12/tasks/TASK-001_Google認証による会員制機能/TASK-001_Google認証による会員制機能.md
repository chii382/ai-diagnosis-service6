# TASK-001 Google認証による会員制機能

## ユーザーニーズ

- 利用者はGoogleアカウントで安全かつ簡単にログインしたい。
- 未ログインの利用者には会員専用ページを見せず、ログイン画面へ案内したい。
- ログイン後、自分の名前・メールアドレス・アバターを確認したい。
- 表示名を変更し、次回以降も変更内容を利用したい。
- 利用者は自分の契約プランと基本プロフィールをダッシュボードで確認したい。
- 性別・年代・職業・自由記入・プロフィール画像を編集し、次回以降も利用したい。

## 仕様要件

### 認証・セッション

- NextAuth.js v5（Auth.js）とGoogle Providerを利用する。
- MongoDB AdapterでGoogleアカウントとユーザー情報をMongoDBに保存する。
- セッション戦略はJWTとし、JWT内のユーザーIDをセッションへ引き継ぐ。
- `/dashboard` と `/profile` は認証必須とする。
- 未認証アクセスは `/auth/signin?callbackUrl=...` へリダイレクトする。
- 認証後の標準遷移先は `/dashboard` とする。
- 「ログアウト」を押した場合は「ログアウトします。よろしいですか？」と確認し、同意した場合のみセッションを終了する。キャンセル時は現在の画面とログイン状態を維持する。
- ログアウト完了後は `/?skipOpening=1#top` へブラウザ遷移し、メッセージ画面と扉画面を表示せずLPヒーローを表示する。

### 画面

- `/auth/signin`: Googleログインボタンを表示する。認証エラー時は案内を表示する。
- `/dashboard`: ユーザー名、アバター、プラン、性別、年代、職業、自由記入の概要と各操作を表示する。
- `/profile`: 名前、メール、性別、年代、職業、自由記入、プロフィール画像を編集・保存できるようにする。
- プランは `free` / `paid` の2値とし、決済連携前の既定値は `free` とする。プロフィール画面からは変更できない。
- 画像はPNG/JPEG/WebP、1MB以下とし、選択直後にプレビューして保存時に他項目と一括更新する。
- 「変更を保存」でDB更新とセッション更新が正常完了した場合、プロフィール画面を終了して遷移元の画面へ戻る。履歴がない場合は `/dashboard` へ遷移する。
- 取得時または直近保存時の値から入力内容が変わっている状態で「ダッシュボードへ戻る」を押した場合、「入力内容は保存されていません。入力を破棄してダッシュボードに戻っても良いですか？」と確認する。同意時のみ入力を破棄して遷移する。
- UIにはMUIの `Button`、`Card`、`Avatar`、`TextField` を使用する。

### API

- `/api/auth/[...nextauth]`: NextAuth.jsのGET/POST認証ハンドラーを提供する（OAuthフロー上POSTも必須）。
- `GET /api/user/profile`: ログインユーザーのプロフィールを返す。
- `PUT /api/user/profile`: `name`, `gender`, `ageGroup`, `occupation`, `bio`, `image` を検証して更新する。
- 未認証は401、不正入力は400、対象ユーザーなしは404、予期しない失敗は500を返す。

### データ・環境変数

- User: `_id`, `name`, `email`, `image`, `plan`, `gender`, `ageGroup`, `occupation`, `bio`, `emailVerified`, `lastLoginAt`, `loginCount`, `createdAt`, `updatedAt`。
- LoginHistory: `_id`, `userId`, `email`, `provider`, `loggedInAt`。認証成功1回につき1レコードを追加する。
- ログイン成功時にUserの `lastLoginAt` を更新し、`loginCount` を1加算する。
- 履歴保存に一時的な障害が発生しても認証成功を取り消さず、サーバーログへエラーを記録する。
- `bio` は500文字以内。未設定の選択項目は「未回答」と表示する。
- Google OAuthで作成された既存ユーザーにも、取得・更新時に日時情報を補完する。
- 必須環境変数: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_SECRET`, `MONGODB_URI`。

## 処理手順設計

### ログイン

1. 利用者が `/auth/signin` のGoogleログインボタンを押す。
2. Auth.jsがGoogle OAuthへ遷移し、コールバックを検証する。
3. MongoDB Adapterがアカウントとユーザーを作成または取得する。
4. Auth.jsがユーザーIDを含むJWTセッションを発行する。
5. `/dashboard` へ遷移し、会員専用情報を表示する。
6. 認証成功イベントで `loginHistory` にユーザーID、メール、プロバイダー、ログイン日時を保存する。
7. Userの最終ログイン日時と累計ログイン回数を更新する。

### 保護ルート

1. ミドルウェアが `/dashboard` または `/profile` へのリクエストを受ける。
2. 有効なJWTセッションがあれば処理を継続する。
3. セッションがなければ、元URLをcallbackUrlとして `/auth/signin` へリダイレクトする。

### ログアウト

1. 利用者がLPヘッダーまたは会員画面の「ログアウト」を押す。
2. 「ログアウトします。よろしいですか？」と確認メッセージを表示する。
3. 同意時のみAuth.jsのログアウト処理をリダイレクトなしで完了させる。
4. セッション終了後、ブラウザを `/?skipOpening=1#top` へ明示的に移動し、メッセージ画面と扉画面をスキップしてLPヒーローを表示する。
5. キャンセル時はログアウトせず、その画面に留まる。

### プロフィール取得・更新

1. プロフィール画面が `GET /api/user/profile` を呼び出す。
2. APIはセッションを検証し、ユーザーID（移行時はメール）でMongoDBを検索する。
3. 編集後、画面が `PUT /api/user/profile` に名前を送信する。
4. APIは前後空白除去、必須、100文字以内を検証し、`name` と `updatedAt` を更新する。
5. DB更新後にセッション情報を再取得し、両方が正常完了した場合は遷移元へ戻る。履歴がない場合はダッシュボードへ遷移する。
6. 未保存変更がある状態でダッシュボードへ戻る場合は破棄確認を表示し、キャンセル時は編集画面に留まる。

## 受け入れ条件

- 必須環境変数を設定するとGoogleでログインでき、`/dashboard` が表示される。
- 未ログインで保護ページを開くとログイン画面へ遷移する。
- ダッシュボードにユーザー名とアバターが表示される。
- プロフィール画面で名前を保存するとMongoDBと画面表示に反映される。
- 保存成功後は遷移元へ戻り、ダッシュボードに更新後の内容が表示される。
- 未保存変更がある場合、確認なしに「ダッシュボードへ戻る」ことができない。
- ログアウト確認をキャンセルすると、ログイン状態と表示中の画面が維持される。
- ログアウト成功後はオープニング演出が表示されず、LPヒーローが直接表示される。
- ログイン成功ごとにLoginHistoryへ履歴が追加され、Userの最終ログイン日時と累計回数が更新される。
- 型チェックと本番ビルドが成功する。
